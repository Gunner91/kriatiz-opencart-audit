KRIATIZ Audit 1.0.0 (бесплатный)
Поиск вирусов и следов взлома, SEO-аудит и проверка языкового закона
для OpenCart / ocStore 2.3 и 3.x
Разработчик: KRIATIZ — https://opencartforum.com/profile/697033-gunner91/

==================================================================
СОВМЕСТИМОСТЬ
==================================================================
- OpenCart 2.3.x.x, 3.x.x.x; ocStore 2.3.x.x, 3.x.x.x
- Один архив для всех версий
- PHP 7.1 и новее (проверено на PHP 7.4, 8.1, 8.2)
- Любой шаблон: модуль работает только в админке
- Не меняет файлы сайта, не добавляет модификаторов (OCMOD)
- ionCube НЕ нужен. Модуль не обращается к серверу разработчика
  и никуда не отправляет данные о вашем магазине.

==================================================================
УСТАНОВКА (2 минуты)
==================================================================
OpenCart / ocStore 3.x:
1. Админка → Расширения → Установка расширений → Загрузить
   файл kriatiz_audit.ocmod.zip.
2. Расширения → Расширения → тип «Модули» → KRIATIZ Audit →
   «Установить» (зелёная кнопка), затем «Редактировать».
3. Нажмите «Проверить магазин».

OpenCart / ocStore 2.3: штатный установщик 2.3 копирует файлы только
через FTP. Если FTP не настроен, залейте содержимое папки upload/
из архива kriatiz_audit.ocmod.zip в корень сайта (FTP или файловый
менеджер хостинга), затем выполните шаги 2–3.

Обновлять модификаторы НЕ нужно.

==================================================================
ЧТО ПРОВЕРЯЕТ (7 этапов, 1–5 минут)
==================================================================
1. Настройки: папка install, права config.php, путь /admin,
   версии PHP и OpenCart, HTTPS, логин «admin», новые администраторы.
2. Ядро OpenCart: каждый файл ядра сверяется с оригиналом вашей
   версии (база контрольных сумм для 14 сборок OpenCart и ocStore).
   Изменённый файл с вредоносным кодом — критическая находка.
3. Все файлы сайта: веб-шеллы, бэкдоры, майнеры, PHP в папке
   изображений, файлы .php.jpg, PHP внутри «картинок», SVG со
   скриптом, «нуленые» модули, вредоносные правила .htaccess,
   Adminer / phpinfo / дампы в корне.
4. База данных: вредоносный код в описаниях товаров, категорий,
   статей, в настройках, баннерах, модулях, модификаторах и отзывах;
   скрытые ссылки и спам-ссылки.
5. Витрина глазами посетителя, Googlebot и смартфона: клоакинг
   (Google видит другое), редиректы для мобильных, скиммер на странице
   оформления, сторонние скрипты, открытые .git / .env / логи /
   бэкапы, листинг папок, ошибки PHP на страницах, заголовки безопасности.
6. SEO: ЧПУ, пустые и одинаковые meta title / description, описания
   товаров, robots.txt, sitemap, корректная 404, редирект на https.
7. Язык и закон: есть ли украинский, открывается ли сайт на украинском,
   настоящий ли украинский языковой пакет витрины, непереведённые
   товары, hreflang, отдельные адреса для языков.

Результат: общая оценка 0–100 и оценки по блокам «Безопасность»,
«SEO», «Язык». Для каждой находки — почему это важно и как исправить.

==================================================================
ВАЖНО
==================================================================
- Модуль ТОЛЬКО ЧИТАЕТ. Он ничего не удаляет и не меняет.
- Сканирование запускается только кнопкой в админке. На скорость
  сайта для посетителей модуль не влияет.
- Некоторые модули намеренно шифруют свой код или подключают сторонние
  скрипты (чаты, аналитика). Если вы уверены, что находка безопасна,
  отметьте её «Это не угроза» — она перестанет влиять на оценку.
- Аудит находит известные признаки взлома. Он не гарантирует
  отсутствие любого вредоносного кода и не заменяет резервные копии.

==================================================================
ЕСЛИ НАЙДЕН ВРЕДОНОСНЫЙ КОД
==================================================================
1. Сделайте резервную копию файлов и базы.
2. Удалите вредоносные файлы и фрагменты по подсказкам.
3. Смените пароли: администраторов, FTP / хостинга, базы данных.
4. Обновите модули и шаблон, через которые мог произойти взлом.
5. Запустите проверку ещё раз.
Не справитесь сами — кнопка «Заказать лечение» в модуле.

==================================================================
УДАЛЕНИЕ
==================================================================
Расширения → Модули → KRIATIZ Audit → «Удалить». Таблицы модуля
(kriatiz_audit_run, kriatiz_audit_issue, kriatiz_audit_ignore)
удаляются. Файлы модуля можно удалить вручную:
admin/controller|model|language|view/.../kriatiz_audit*,
system/library/kriatiz/audit/.
