KRIATIZ Audit 1.0.0 (безкоштовний)
Пошук вірусів і слідів злому, SEO-аудит і перевірка мовного закону
для OpenCart / ocStore 2.3 і 3.x
Розробник: KRIATIZ — https://opencartforum.com/profile/697033-gunner91/

==================================================================
СУМІСНІСТЬ
==================================================================
- OpenCart 2.3.x.x, 3.x.x.x; ocStore 2.3.x.x, 3.x.x.x
- Один архів для всіх версій
- PHP 7.1 і новіше (перевірено на PHP 7.4, 8.1, 8.2)
- Будь-який шаблон: модуль працює лише в адмінці
- Не змінює файли сайту, не додає модифікаторів (OCMOD)
- ionCube НЕ потрібен. Модуль не звертається до сервера розробника
  і нікуди не надсилає дані про ваш магазин.

==================================================================
ВСТАНОВЛЕННЯ (2 хвилини)
==================================================================
OpenCart / ocStore 3.x:
1. Адмінка → Розширення → Встановлення розширень → Завантажити
   файл kriatiz_audit.ocmod.zip.
2. Розширення → Розширення → тип «Модулі» → KRIATIZ Audit →
   «Встановити» (зелена кнопка), потім «Редагувати».
3. Натисніть «Перевірити магазин».

OpenCart / ocStore 2.3: штатний установщик 2.3 копіює файли лише
через FTP. Якщо FTP не налаштовано, залийте вміст папки upload/
з архіву kriatiz_audit.ocmod.zip у корінь сайту (FTP або файловий
менеджер хостингу), потім виконайте кроки 2–3.

Оновлювати модифікатори НЕ потрібно.

==================================================================
ЩО ПЕРЕВІРЯЄ (7 етапів, 1–5 хвилин)
==================================================================
1. Налаштування: папка install, права config.php, шлях /admin,
   версії PHP і OpenCart, HTTPS, логін «admin», нові адміністратори.
2. Ядро OpenCart: кожен файл ядра звіряється з оригіналом вашої
   версії (база контрольних сум для 14 збірок OpenCart і ocStore).
   Змінений файл зі шкідливим кодом — критична знахідка.
3. Усі файли сайту: веб-шели, бекдори, майнери, PHP у папці
   зображень, файли .php.jpg, PHP усередині «картинок», SVG зі
   скриптом, «нульовані» модулі, шкідливі правила .htaccess,
   Adminer / phpinfo / дампи в корені.
4. База даних: шкідливий код в описах товарів, категорій, статей,
   у налаштуваннях, банерах, модулях, модифікаторах і відгуках;
   приховані посилання та спам-посилання.
5. Вітрина очима відвідувача, Googlebot і смартфона: клоакінг
   (Google бачить інше), редиректи для мобільних, скімер на сторінці
   оформлення, сторонні скрипти, відкриті .git / .env / логи /
   бекапи, лістинг папок, помилки PHP на сторінках, заголовки безпеки.
6. SEO: ЧПУ, порожні та однакові meta title / description, описи
   товарів, robots.txt, sitemap, коректна 404, редирект на https.
7. Мова і закон: чи є українська, чи відкривається сайт українською,
   чи справжній український мовний пакет вітрини, неперекладені
   товари, hreflang, окремі адреси для мов.

Результат: загальна оцінка 0–100 і оцінки за блоками «Безпека»,
«SEO», «Мова». Для кожної знахідки — чому це важливо і як виправити.

==================================================================
ВАЖЛИВО
==================================================================
- Модуль ТІЛЬКИ ЧИТАЄ. Він нічого не видаляє і не змінює.
- Сканування запускається лише кнопкою в адмінці. На швидкість
  сайту для відвідувачів модуль не впливає.
- Деякі модулі навмисно шифрують свій код або підключають сторонні
  скрипти (чати, аналітика). Якщо ви впевнені, що знахідка безпечна,
  позначте її «Це не загроза» — вона перестане впливати на оцінку.
- Аудит знаходить відомі ознаки злому. Він не гарантує відсутність
  будь-якого шкідливого коду і не замінює резервні копії.

==================================================================
ЯКЩО ЗНАЙДЕНО ШКІДЛИВИЙ КОД
==================================================================
1. Зробіть резервну копію файлів і бази.
2. Видаліть шкідливі файли та фрагменти за підказками.
3. Змініть паролі: адміністраторів, FTP / хостингу, бази даних.
4. Оновіть модулі й шаблон, через які міг статися злом.
5. Запустіть перевірку ще раз.
Не впораєтеся самі — кнопка «Замовити лікування» в модулі.

==================================================================
ВИДАЛЕННЯ
==================================================================
Розширення → Модулі → KRIATIZ Audit → «Видалити». Таблиці модуля
(kriatiz_audit_run, kriatiz_audit_issue, kriatiz_audit_ignore)
видаляються. Файли модуля можна видалити вручну:
admin/controller|model|language|view/.../kriatiz_audit*,
system/library/kriatiz/audit/.
